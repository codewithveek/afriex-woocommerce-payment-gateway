Accept bank transfer payments through Afriex virtual accounts. Orders are confirmed automatically when the deposit arrives.

== Description ==

Afriex Gateway for WooCommerce adds Afriex as a payment method in your store. At checkout the customer is given bank account details generated by Afriex. When the transfer lands, Afriex notifies your store and the order moves to a paid status on its own — no manual reconciliation.

**How it works**

1. The customer places an order and chooses Afriex.
2. The plugin asks Afriex for an account to collect into, and shows the details on the order-received page and in the order email.
3. The order is held at **On hold** while the store waits for the transfer.
4. Afriex sends a signed webhook when the deposit is confirmed, and the order moves to **Processing** or **Completed**.

**Two ways to collect**

* **Dedicated virtual account** — a unique account per order. The customer does not have to type a reference, and nothing depends on them getting it right.
* **Pool account** — one shared account, with a payment reference per order. Lighter to operate at higher volume, but the customer must include the reference.

**Built for current WooCommerce**

* Works on both the classic shortcode checkout and the Cart & Checkout blocks.
* Compatible with High-Performance Order Storage (HPOS).
* Webhook signatures are verified with RSA-SHA256 before anything is read or written.
* An hourly reconciliation sweep confirms orders even if a webhook is lost in transit.
* Payments whose amount does not match the order total are flagged for review rather than auto-completed.

== External services ==

This plugin connects to the Afriex API to create the account a customer pays into and to confirm that payment. The plugin does not function without it.

**What is sent, and when**

* **When a customer places an order using Afriex:** their billing name, email address, phone number and billing country are sent to Afriex to create or match a customer record; the order total and currency are sent to generate the collection account.
* **When the plugin checks on an unpaid order (hourly, and only for orders awaiting payment):** the Afriex payment method identifier stored against the order is sent so the transaction can be looked up.

**What is received**

* Account details (bank, account name, account number, reference) shown to the customer.
* Payment status notifications, delivered to `/wp-json/afriex/v1/webhook` on your site and signed by Afriex.

Service provider: Afriex — https://afriex.com

No data is sent to Afriex for visitors who do not choose Afriex as their payment method.

== Installation ==

1. Install and activate the plugin.
2. Go to **WooCommerce > Settings > Payments** and enable **Afriex**.
3. Paste your **API Key** from **Settings > API Keys** in the Afriex Business dashboard.
4. Paste your **Webhook Public Key** from **Developers > Webhooks** in the same dashboard.
5. In the Afriex dashboard, point your webhook at the URL shown in the plugin's settings screen: `https://your-store.example/wp-json/afriex/v1/webhook`
6. Choose a collection method, save, and place a sandbox order to confirm the flow end to end.

The webhook public key is not optional. Without it every payment confirmation is rejected and orders stay on hold.

== Frequently Asked Questions ==

= Why does my order sit at "On hold" after checkout? =

That is the intended state. A bank transfer is not confirmed at checkout — the customer still has to send the money. The order moves on when Afriex confirms the deposit. If an order stays on hold long after the transfer, check that the webhook URL and public key are set correctly; the hourly reconciliation sweep will also catch it.

= The payment method does not appear on my checkout. =

Check that an API key is saved. The gateway hides itself when it cannot actually take a payment. If you use the Cart & Checkout blocks, also confirm the plugin's JavaScript bundle was built — a release ZIP includes it.

= What happens if a customer pays the wrong amount? =

The order is not completed. A note is added recording what arrived and what was expected, and the order is left for you to review.

= Does this work with High-Performance Order Storage? =

Yes. All order data is read and written through the WooCommerce CRUD API, and the plugin declares HPOS compatibility.

= Can I refund through this plugin? =

Not in this version. Refunds are planned once the Afriex refund path is confirmed as API-accessible. If Afriex reports a payment as refunded, the plugin adds an order note so you can record the refund in WooCommerce yourself.
